Знакомство

Что это за проект

«Импульс» — интернет-магазин электроники: наушники и колонки, смартфоны и часы, камеры, техника для работы и чтения. В каталоге 24 товара в четырёх разделах, цены от 9 990 до 229 990 ₽. Проект состоит из трёх частей, которые работают как одно целое.

Витрина

Сайт для покупателей: каталог с фильтрами, умный поиск, карточки товаров, корзина, оформление с оплатой картой или при получении, статус заказа и возврат.

Личный кабинет

Регистрация и вход, история заказов с таймлайном доставки, профиль. Корзина и избранное синхронизируются между устройствами.

Управление

Раздел для команды магазина: заказы и их статусы, товары и остатки с загрузкой фото, модерация отзывов, возвраты, пользователи и роли, журнал действий.

API

Сервер на NestJS и PostgreSQL. Отвечает за цены, остатки, оплату через ЮKassa, письма и права доступа. Витрина и управление работают только через него.

Быстрый старт

Для запуска нужны Node.js 24+ и Docker Desktop. Команды выполняются из корня проекта.

  1. Поднимите базу и почтовый перехватчик. 
    cd server
cp .env.example .env        # затем впишите длинный случайный JWT_ACCESS_SECRET
npm install
npm run db:up               # PostgreSQL на :5440, Mailpit на :8025
npm run db:deploy           # применить миграции
npm run db:seed             # каталог, отзывы, первый администратор
  2. Запустите API. 
    npm run start:dev           # http://localhost:3000/api/v1
  3. Запустите витрину во втором терминале, из корня проекта. 
    npm install
npm run dev                 # http://localhost:5173, /api проксируется на :3000

Витрина и кабинет

Главная, каталог и поиск

Сайт выдержан в сдержанной премиальной стилистике. По умолчанию тёмная тема, переключатель солнца в шапке включает светлую. Страницы сменяются плавно, без перезагрузки.

Каталог

  • Фильтры слева: раздел, потолок цены и «Только в наличии». Рядом с каждым вариантом показано, сколько товаров останется; варианты без товаров выключаются, а не прячутся.
  • Все фильтры хранятся в адресе страницы, например /catalog?cat=sound&max=20000&stock=1. Такой ссылкой можно поделиться, а фильтры переживают перезагрузку.
  • Сортировка: популярные, дешевле, дороже.

Поиск

Открывается по Ctrl+K (⌘+K на Mac), клавишей / или кнопкой в шапке. Поиск понимает:

  • опечатки и неверную раскладку: «ыщтн» найдёт Sony;
  • транслит и цвета: «чёрные наушники»;
  • цену и наличие словами: «до 30 000», «в наличии»;
  • сценарии из тегов товара: «для бега», «в подарок»;
  • вопросы про сервис: «возврат» открывает раздел помощи.

Если запрос исправлен, поиск предложит «Возможно, вы имели в виду».

Карточка товара и отзывы

  • Галерея листается стрелками и свайпом. При выборе цвета показывается фото именно этого цвета.
  • У кнопки покупки есть дата доставки (а не «1–2 дня»), итог с доставкой и условие возврата за 30 дней.
  • Если товара нет, вместо кнопки «В корзину» появляется подписка «Сообщить о поступлении». Письмо придёт, как только остаток станет больше нуля.
  • Габариты «в масштабе» и характеристики идут единым словарём, его же читает подборщик.

Отзывы. Публикуются только отзывы покупателей с доставленным заказом этого товара, каждый проходит модерацию. Чтобы написать отзыв, нужно войти в аккаунт. Для гостя форма показывает приглашение войти.

Корзина и оформление

Корзина хранится в браузере и не теряется при перезагрузке. Если покупатель вошёл в аккаунт, она синхронизируется с ним. Удаление товара можно отменить в подсказке внизу, шкала показывает, сколько осталось до бесплатной доставки от 20 000 ₽.

Что важно знать об оформлении

  • Цену считает сервер. Если цена изменилась, пока товар лежал в корзине, заказ не оформится по старой. Корзина сама обновит цены, покупатель увидит сообщение и подтвердит заказ ещё раз. То же с товаром, который закончился (останется доступное количество) или снят с продажи (уберётся).
  • Двойной клик не создаёт два заказа. Каждая попытка оформления несёт ключ идемпотентности. Повтор того же заказа, например после пропавшей связи, вернёт уже созданный.
  • Резерв товара. Товар списывается с остатка в момент оформления. Последнюю единицу нельзя продать двоим.
  • Доставка. Курьером 390 ₽, бесплатно от 20 000 ₽. Самовывоз бесплатно. Дата доставки рассчитывается по московскому времени: после 16:00 срок сдвигается на день.
  • Вошедшему покупателю имя и телефон подставляются сами.

Оплата

При получении

Заказ сразу получает статус «Оформлен», покупателю уходит письмо с подтверждением.

Картой онлайн

Покупатель переходит на страницу ЮKassa и возвращается на «Заказ принят». Страница сама уточняет у сервера, прошла ли оплата. Резерв держится 30 минут, затем неоплаченный заказ отменяется, а товар возвращается на склад.

В разработкеВместо ЮKassa работает тестовая страница оплаты прямо в API с кнопками «Оплатить» и «Отменить». Деньги не списываются. В продакшене тестовый режим запрещён: API с ним не запустится.

Статус заказа и возврат

В разделе «Помощь» покупатель узнаёт, где заказ, по номеру и телефону, без входа в аккаунт. Ответ для несуществующего номера и для неверного телефона одинаковый, поэтому чужой заказ так не найти.

Возврат оформляется там же в два шага: номер заказа, телефон и причина (необязательно), затем подтверждение. Вернуть можно полученный заказ в течение 30 дней. Покупатель получает номер заявки вида RT-4892-1010-32, менеджер видит её в разделе «Возвраты».

Вход и личный кабинет

Регистрация занимает одну форму: имя, почта, пароль и, по желанию, телефон. Пароль — от 8 символов, с буквой и цифрой. Покупать можно и без аккаунта.

В кабинете три раздела: заказы, профиль и пароль, а для сотрудников ещё ссылка «Управление магазином».

  • Заказы: все заказы аккаунта со статусом и суммой, новые сверху.
  • Карточка заказа: таймлайн доставки с датами, состав, сумма, адрес. Для неоплаченного заказа — кнопка «Оплатить».
  • Профиль: имя и телефон. При смене пароля выход происходит на всех устройствах.
СинхронизацияПосле входа корзина и избранное гостя объединяются с аккаунтом: у совпадающих позиций берётся большее количество. Дальше изменения сохраняются на сервере и видны на всех устройствах. После выхода, в том числе по истечении сессии или после смены пароля, данные аккаунта стираются с устройства, на сервере они остаются.

Мобильная версия

Все страницы рассчитаны на экран от 320 px. Кнопки и поля не меньше 44 px, текст в полях 16 px, чтобы iPhone не увеличивал страницу. Меню открывается шторкой справа, фильтры каталога — шторкой снизу.

Управление магазином

Роли и доступ

Управление открывается по адресу /admin или из кабинета: «Управление магазином». Покупатель на этом адресе видит обычную страницу 404. Права проверяет сервер на каждом запросе, поэтому снятая роль перестаёт действовать сразу.

Сводка

Первый экран управления: выручка за 30 дней (без отменённых и неоплаченных), заказы за сегодня, средний чек, отзывы на модерации, открытые возвраты, заказы по статусам и товары, которых осталось три штуки и меньше. Счётчики у пунктов «Отзывы» и «Возвраты» в меню показывают, сколько работы ждёт.

Заказы

Список ищет по номеру, имени, почте и последним цифрам телефона и фильтруется по статусу. Фильтры хранятся в адресе, ссылку на выборку можно отправить коллеге.

Товары и остатки

Список показывает все товары, включая снятые с продажи. Есть поиск по названию, бренду и адресу, фильтр по разделу и быстрые фильтры: «Заканчиваются», «Нет в наличии», «Сняты с продажи».

Как поменять остаток

  1. Нажмите на число в колонке «Остаток, шт.».
  2. Введите новое значение и нажмите Enter или кликните мимо поля. Esc отменяет правку.
  3. Подсказка внизу подтвердит сохранение. Если остаток был нулевым, подписчикам «Сообщить о поступлении» сразу уйдут письма.
Почему остаток не меняется в карточке товараПока менеджер редактирует карточку, товар могут купить. Если бы форма сохраняла остаток, она записала бы старое число поверх продаж. Поэтому остаток меняется только в таблице, и сервер при этом блокирует строку товара.

Редактирование товара

Клик по названию открывает редактор: основное, цена, цвета и варианты, фото, характеристики, габариты, теги и показ на витрине. Справа видно, есть ли несохранённые правки. Изменения появятся на витрине в течение минуты.

Снять с продажи можно галочкой «Продаётся» в разделе «Поиск и показ». Товар исчезнет с витрины, из корзин и избранного, но останется в истории заказов. Удалять товары нельзя намеренно: на них ссылаются прошлые заказы.

Добавление товара

«Товары» → кнопка «Добавить товар» справа от заголовка.

  1. Основное. Название, бренд, тип товара («Наушники»), раздел и описание: чем хорош, кому подойдёт, что в коробке. Адрес на сайте подставится автоматически, например «Nothing Ear (3)» → nothing-ear-3.
  2. Цена и наличие. Цена в рублях. «До скидки» заполняйте, только если есть скидка: она должна быть выше цены. Остаток в штуках, 0 — нет в наличии.
  3. Цвета и варианты. Хотя бы один цвет с оттенком. «Название выбора» — «Комплект», «Память», «Размер»; варианты пишутся по одному в строке, например «128 ГБ» и «256 ГБ».
  4. Фото. Загрузите одно или несколько фото сразу. На каждом кадре укажите цвет и короткое описание для незрячих. Отметьте «Фото для карточки» — оно будет в каталоге. Порядок в галерее меняется стрелками.
  5. Характеристики. Пишите названия так же, как у других товаров: «Работа от батареи», «Экран», «Вес». Подборщик техники читает их по названиям.
  6. Габариты, теги, показ. Размер, вес и понятное сравнение («как спичечный коробок»). Теги — сценарии и синонимы через запятую: «для бега», «в подарок». Популярность от 0 до 1000 задаёт порядок в каталоге.
  7. Сохраните кнопкой «Добавить товар» справа. Если отмечено «Продаётся», товар сразу появится на витрине.

Требования к фото

  • JPEG, PNG, WebP или AVIF до 15 МБ. Минимум 320 × 320 px, лучше от 1600 px по ширине.
  • Фото для карточки — на светлом спокойном фоне, товар целиком. Остальные — детали и товар в жизни.
  • Сервер сам пережимает фото в AVIF и WebP шести размеров (160–1600 px), делает размытое превью и определяет средний цвет. Новые карточки в сетке не отличаются от старых. Оригинал не хранится.
  • Если переименовать или удалить цвет, фото этого цвета переходят на новое название или на первый оставшийся цвет.

Отзывы

Раздел открывается на очереди «На модерации». Для каждого отзыва есть товар, оценка, автор, дата и отметка «покупка подтверждена». Решение — кнопки «Опубликовать» или «Отклонить». Опубликованный отзыв можно снять, отклонённый — опубликовать позже.

ПолитикаПубликуйте и критичные отзывы: стена пятёрок выглядит фальшиво и скрывает реальные минусы. Отклоняйте оскорбления, рекламу и отзывы не о товаре.

Возвраты

  1. Новая. Покупатель оформил заявку на сайте. Позвоните ему и договоритесь, как передать товар. Затем нажмите «Одобрить» или «Отклонить».
  2. Одобрена. Ждём товар. Когда он пришёл и проверен, верните деньги в личном кабинете платёжного сервиса (для оплаты при получении — тем же способом, что и оплата).
  3. Завершена. Нажмите «Товар получен, деньги вернули». Заявка закрыта.
Деньги по заявке возвращаются вручнуюАвтоматически деньги уходят только при отмене оплаченного заказа. Возврат по заявке бывает частичным, поэтому сумму определяет менеджер.

Пользователи и журнал

Только для администраторов. В «Пользователях» есть поиск по имени, почте и телефону и фильтр по роли. Чтобы сменить роль, выберите её в списке и нажмите «Сменить». Пользователю придётся войти заново. Снять роль с последнего администратора система не даст, свою роль поменять нельзя.

Управление с телефона

Всё управление работает на телефоне. Разделы переносятся на две строки, широкие таблицы прокручиваются вбок внутри себя, кнопки статусов стоят под карточкой заказа.

Ошибки

Любая ошибка возвращается как RFC 9457 application/problem+json с машинным code, человеческим detail и requestId для поиска в логах. У ошибок валидации есть errors: [{ field, message }]. Неизвестные поля в запросе отклоняются.

HTTP/1.1 409 Conflict
Content-Type: application/problem+json

{
  "type": "https://impulse.store/problems/price-changed",
  "status": 409,
  "code": "PRICE_CHANGED",
  "detail": "Цены изменились. Проверьте корзину и подтвердите заказ ещё раз",
  "lines": [{ "productId": 1, "colorName": "Чёрный", "option": "Наушники с чехлом", "price": 32990 }],
  "requestId": "6f1c…"
}

Авторизация

  • Пароли хэшируются argon2id. Ответ при неизвестной почте такой же и по тексту, и по времени, как при неверном пароле.
  • Access-токен — JWT на 15 минут, хранится только в памяти страницы. Refresh-токен — случайная строка в httpOnly-cookie (SameSite=Strict, путь /api/v1/auth), в базе только её SHA-256.
  • Refresh ротируется при каждом использовании. Старый токен принимается ещё 30 секунд — так обновляются параллельные вкладки. Позже это признак кражи: отзывается вся цепочка сессий. После выхода, смены пароля или роли старый токен не работает даже в эти 30 секунд.
  • POST /auth/refresh без cookie отвечает 204: это гость, а не ошибка. Витрина спрашивает при каждом запуске, а без сети повторяет попытку, когда связь вернётся.
  • Роль сотрудника сверяется с базой на каждом запросе к управлению.

Развёртывание

Рекомендуемая схема — витрина и API на одном домене: статика витрины отдаётся веб-сервером, /api проксируется в контейнер API. Так refresh-cookie остаётся SameSite=Strict, а CORS не нужен.

  1. Соберите витрину: npm ci && npm run build в корне. Содержимое dist/ вместе с public/media положите на веб-сервер. Все неизвестные пути должны отдавать index.html (SPA).
  2. Соберите и запустите API: docker build -t impulse-api server. Образ многоступенчатый, работает не от root, с HEALTHCHECK. Перед стартом он сам выполняет prisma migrate deploy.
  3. Подключите тома: данные PostgreSQL и папку /app/uploads — в ней фото, загруженные в управлении.
  4. Настройте прокси: location /api/ → контейнер API на порту 3000, заголовки X-Forwarded-For и X-Forwarded-Proto. В API выставьте TRUST_PROXY=1.
  5. Заполните каталог один раз: docker exec … npx prisma db seed.
  6. ЮKassa: в личном кабинете укажите вебхук https://ваш-домен/api/v1/payments/webhooks/yookassa на события payment.succeeded и payment.canceled.

Для проверки всего стека локально: docker compose --profile app up --build в папке server поднимет PostgreSQL, Mailpit и API в контейнере.

Эксплуатация

  • Логи — одна строка JSON на запрос (pino) с X-Request-Id. Тот же id приходит в ответе с ошибкой — по нему находится запрос. Токены, cookie и пароли в логи не попадают.
  • Мониторинг: /api/health — процесс жив, /api/health/ready — есть связь с базой. При непредвиденной ошибке API пишет её в лог, аккуратно закрывается и перезапускается оркестратором.
  • Лимиты запросов с одного IP: 120 в минуту в целом; вход и регистрация — 10, оформление и трекинг — 10, возвраты и отзывы — 5.
  • Резервные копии: ежедневный pg_dump и копия папки uploads. Фото каталога из сида лежат в репозитории (public/media).
  • Новая миграция: правка schema.prisma → npm run db:migrate -- --name описание → коммит папки миграции. На сервере она применится при старте контейнера.

Решение проблем

СитуацияЧто проверить
Не приходит письмоВ разработке — Mailpit, localhost:8025. В продакшене — таблица OutboxMessage: статус FAILED и поле lastError покажут причину (обычно SMTP или DNS отправителя).
Заказ завис в «Ждёт оплаты»Через 30 минут он отменится сам. Если покупатель уверен, что оплатил, откройте заказ в управлении: раздел «Оплата» показывает статус платежа. Опоздавшая оплата вернётся автоматически.
Возврат денег не прошёлПлатёж в статусе REFUND_PENDING — задача повторяет каждые 5 минут. В логах ищите «Refund of payment … failed».
Товар не появился на витринеОтмечено ли «Продаётся», есть ли фото для карточки. Снимок каталога обновляется в течение минуты.
Вебхуки ЮKassa получают 403Не задан или неверен TRUST_PROXY — API видит IP прокси вместо IP ЮKassa.
Все разлогинилисьСменился JWT_ACCESS_SECRET или истекли сессии (REFRESH_TTL_DAYS).
Забыт пароль администратораСид не меняет пароль существующей почты. Зарегистрируйте новый аккаунт на сайте, затем в Prisma Studio (npm run db:studio) поставьте ему роль ADMIN в таблице User. После входа смените пароль старого аккаунта или снимите с него роль.
API не стартуетСообщение в консоли называет переменную: обычно DATABASE_URL, короткий JWT_ACCESS_SECRET, TRUST_PROXY или mock-оплата в продакшене.
Порт 5440 занятЗадайте другой в POSTGRES_PORT для docker compose и поправьте DATABASE_URL.
