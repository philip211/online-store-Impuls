# Импульс — магазин электроники

Автор — [philip211](https://github.com/philip211) · репозиторий: [github.com/philip211/online-store-Impuls](https://github.com/philip211/online-store-Impuls)

Витрина на React по методологии **Feature-Sliced Design**. Исходный макет лежит в [design-reference/](design-reference/). Текущий визуальный язык — его сдержанная премиальная редакция (см. «Дизайн-система»).

## Документация

Полное руководство со скриншотами десктопа и телефона — [docs/index.html](docs/index.html): витрина и кабинет, работа в управлении магазином, архитектура, API, развёртывание и решение проблем.

## Скрипты

Сначала поднимите API (подробно в [server/README.md](server/README.md)):

```bash
cd server && npm install && npm run db:up && npm run db:deploy && npm run db:seed && npm run start:dev
```

Затем витрину:

```bash
npm install
npm run dev        # дев-сервер, /api проксируется на localhost:3000
npm run build      # проверка типов и прод-сборка
npm run preview    # просмотр сборки
npm run lint       # ESLint
npm run lint:fsd   # Steiger: правила FSD
npm test           # Vitest
npm run media      # пересобрать фотографии каталога (см. «Фотографии»)
```

## Архитектура (FSD)

```
src/
├── app/        # точка входа, провайдеры, роутер, глобальные стили и токены
├── pages/      # home, catalog, product, cart, order-success, help, favorites, finder,
│               # login, account (кабинет), admin (управление), not-found
├── widgets/    # header, footer, hero, category-showcase, trust-bar,
│               # product-grid, product-details, product-reviews, cart-checkout
├── features/   # add-to-cart, filter-products, edit-cart-line, checkout, toggle-theme,
│               # auth, sync-account, write-review …
├── entities/   # product, cart, review, wishlist, session, order
└── shared/     # ui-kit, lib, api, config
```

- Слой импортирует только нижележащие слои, и только через публичный API слайса (`index.ts`). Это проверяют ESLint (`no-restricted-imports`) и Steiger.
- Перекрёстный импорт между сущностями, если понадобится, идёт только через `@x`. Сейчас корзина хранит лишь id товара и фото, поэтому `@x` не нужен.
- В слайсах есть сегменты `ui`, `model`, `api`, `lib`.

## Ключевые решения

- **API** живёт в [server/](server/README.md). Сегменты `api` слайсов (`productApi`, `reviewApi`, `placeOrder`, `trackOrder`…) ходят в него через `shared/api/http.ts`, ошибки приходят как RFC 9457 и превращаются в `ApiError` с полем `code`. Оформление идемпотентно: повтор того же заказа отправляется с тем же `Idempotency-Key`. При оплате картой покупатель уходит на страницу оплаты, а страница «Заказ принят» после возврата спрашивает у API, прошла ли оплата.
- **Аккаунт.** Сущность `session` держит access-токен только в памяти. При старте тихо запрашивает `/auth/refresh` (у гостя без cookie API отвечает 204, консоль чистая), после 401 один раз продлевает сессию и повторяет запрос. Одновременные продления схлопываются в одно, чтобы ротируемая cookie не тратилась дважды. `/login` — вход и регистрация, `?next=` принимает только пути этого сайта.
- **Синхронизация** (`features/sync-account`): после входа корзина и избранное гостя объединяются с аккаунтом (у совпадающих позиций берётся большее количество), затем изменения уходят на сервер. При выходе с устройства всё стирается.
- **Кабинет** `/account`: заказы с таймлайном доставки и оплатой неоплаченного, профиль, смена пароля. Оформление подставляет имя и телефон вошедшего.
- **Управление** `/admin` (менеджер, администратор): сводка, заказы со сменой статусов по статусной машине и историей, товары: добавление и редактирование (цвета, варианты, характеристики, габариты, загрузка фото с выбором фото карточки и цвета каждого кадра), остаток правится прямо в таблице; модерация отзывов, возвраты; администратору также пользователи с ролями и журнал. Отдельный чанк, витрина его не загружает. Фильтры списков живут в URL. Покупатель на `/admin` видит обычную 404.
- **Отзывы** (`features/write-review`): форма на странице товара; API пропускает только покупателей с доставленным заказом и отправляет отзыв на модерацию.
- **Фильтры каталога хранятся в URL** (`?cat=sound&max=20000&stock=1&sort=price-asc`), поэтому ссылкой на выборку можно поделиться, а состояние переживает перезагрузку страницы.
- **Loaders и `ensureQueryData`**: данные главной и карточки товара грузятся параллельно с JS-чанком страницы, без каскада запросов.
- **Корзина** хранит снимок товара (цена, вариант) и сохраняется в `localStorage`.
- **Тема** применяется до первой отрисовки (inline-скрипт в `index.html`), поэтому страница не мигает.
- **Доступность**: skip-link, `aria-live` для тостов и счётчиков, `aria-pressed` и `aria-invalid`, фокус-кольца. При `prefers-reduced-motion` все анимации отключаются.
- **Анимации**: появление при скролле через `animation-timeline: view()` (прогрессивное улучшение), полёт товара в корзину через WAAPI, 3D-наклон через CSS-переменные.
- **Бесшовность (View Transitions)**: страницы сменяются плавно, шапка при этом не перерисовывается. Плитка товара «перетекает» в галерею на странице товара (имена `pbox-*`/`part-*` включаются только на время перехода). Тема переключается круговым раскрытием от кнопки. В браузерах без этого API работает CSS-фолбэк.
- **Поиск** (`features/search-products`): палитра по Ctrl/⌘+K или `/`. Это combobox с `aria-activedescendant`: навигация стрелками, подсветка всех слов запроса, история запросов, переход к полным результатам в каталог (`?q=`).
- **Модальные окна** на нативном `<dialog>`: ловушка фокуса, закрытие по Esc, анимации появления и закрытия через `@starting-style`. Мобильное меню — шторка справа.
- **Избранное** (`entities/wishlist`) и **«Вы смотрели»** хранятся в `localStorage`.
- **UX корзины**: удаление можно отменить в тосте, шкала показывает, сколько осталось до бесплатной доставки, черновик формы живёт в `sessionStorage` до конца сессии вкладки.
- **Каталог**: при смене фильтров прежние результаты остаются приглушёнными (без мигания скелетона), на мобильной кнопке «Фильтры» виден счётчик активных фильтров.
- **Галерея** листается стрелками с клавиатуры и свайпом на телефоне.

## Фотографии

Сдержанный дизайн держится на съёмке, поэтому векторных рисунков больше нет: каждая карточка, галерея, корзина, поиск и главная показывают фотографии.

- **Источник и лицензия.** 51 фотография с [Unsplash](https://unsplash.com) по [Unsplash License](https://unsplash.com/license): бесплатно, без разрешения, указание автора приветствуется. Автор и ссылка на оригинал хранятся у каждого фото, подпись «Фото: Автор / Unsplash» стоит под галереей и в главном блоке. Полный список — [media/CREDITS.md](media/CREDITS.md) (генерируется, не править вручную).
- **Манифест.** `media/catalog-images.json` — единственный источник: файл, товар, роль (`primary`, `gallery`, `context`), цвет, alt-текст, фокус кадра, тон и автор. Оригиналы лежат в `media/originals/<slug>/<n>.jpg`.
- **Сборка.** `npm run media` (`scripts/build-media.mjs`, на sharp) делает AVIF и WebP шириной 480, 800, 1200 и 1600 px в `public/media/<slug>/`: без метаданных, без увеличения, с одной общей лёгкой цветокоррекцией (насыщенность ×0,94), чтобы стоковые кадры читались как одна съёмка. Заодно пишутся `entities/product/api/media.generated.ts` (размеры, размытое превью 16 px, средний цвет) и `CREDITS.md`. Первый прогон около 4 минут, повторные пропускают неизменённые файлы (секунды); `npm run media -- --force` пересобирает всё. В `public/media` 408 файлов, около 15 МБ.
- **Вывод.** Компонент `ProductImage` (`entities/product`) рисует `<picture>` с AVIF и WebP, `sizes`, размерами против сдвига вёрстки, фокусом кадра и размытым превью, которое гаснет за `--dur-slow`. По умолчанию фото грузится лениво; главное фото героя, галереи и первых карточек каталога — с `priority` (`fetchpriority="high"`). `getImage(product, { role, color })` выбирает кадр под цвет, затем по роли, затем главный.
- **Добавить товар** проще всего в админке: «Управление → Товары → Добавить товар». Фото загружаются там же, и API кодирует их так же, как этот конвейер. Конвейер остаётся для каталога из сида: оригинал в `media/originals/<slug>/`, описание в манифесте, `npm run media`.

## Дизайн-система

Задача — тихая роскошь без приёмов, которые сейчас выдают сгенерированный интерфейс.

- **Одна гарнитура** — Onest Variable (российский гротеск, полная кириллица). Заголовки в обычном регистре, вес 600, плотная разрядка (−0.035…−0.05em). Словесный знак набран капителью с широкой разрядкой.
- **Цвет**: тёплые нейтральные тона. Лайм — только заливка главной кнопки и бейджа скидки. «Акцентный текст» равен основному цвету: акцент создаётся весом, а не цветом.
- **Поверхности плоские**: никаких свечений, переливов текста, стекла, зерна, сеток и орбит. Разделение — волосяные линии.
- **Движение**: одна кривая quint-out без «пружин», малые смещения, никаких бесконечных анимаций на контенте. Переходы между страницами — View Transitions.
- **Честный контент**: нет таймеров срочности и выдуманного рейтинга. Бренды — статичная строка, а не бегущая.
- **Иконки** с линией 1.5px. Радиокнопки и чекбоксы нарисованы вручную.
- **Бюджет**: стартовый JS ≈ 60 КБ (20 КБ gzip) плюс общие чанки React, Router и Query; кабинет, вход и управление (≈ 38 КБ) грузятся только на своих маршрутах. Zod грузится только в корзине, данные каталога с метаданными фото — отдельным чанком при первом запросе.
